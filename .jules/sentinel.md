## 2024-05-18 - SSRF Vulnerability via requests.get without redirect protection
**Vulnerability:** The application was vulnerable to Server-Side Request Forgery (SSRF) when downloading category/product images. `requests.get` was used on unverified user input without disabling redirects.
**Learning:** Even if a URL's hostname is validated against an allowlist, an attacker can bypass this if the allowed host has an open redirect vulnerability or redirects to internal IPs, because `requests.get` follows redirects by default.
**Prevention:** To prevent SSRF in Python/Django, always use a two-pronged approach: 1) strictly validate the URL scheme and ensure the hostname is in an explicit allowlist, AND 2) explicitly pass `allow_redirects=False` to `requests.get()` to prevent attackers from bypassing host validation via open redirects.
