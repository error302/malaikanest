## 2026-09-06 - Strict SSRF Prevention with `allow_redirects=False`
**Vulnerability:** A Server-Side Request Forgery (SSRF) vulnerability existed in `AdminCategorySerializer` and `AdminProductSerializer` due to unsafe usage of `requests.get()` with user-supplied Image URLs.
**Learning:** Using `requests.get` with standard `allow_redirects=True` (the default) allows an attacker to supply a seemingly safe URL that passes domain checks but triggers a 301/302 redirect to an internal IP (like 127.0.0.1 or AWS metadata), bypassing naive host filters entirely.
**Prevention:** To thoroughly mitigate SSRF when downloading external resources in this codebase: 1) parse the URL and strictly validate both scheme (`https`) and hostname against an explicit allowlist (e.g., `IMAGE_URL_ALLOWED_HOSTS`), and crucially, 2) ALWAYS set `allow_redirects=False` on the `requests.get` call.
