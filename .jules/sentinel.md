## 2026-09-15 - SSRF Vulnerability in Admin Image Downloads
**Vulnerability:** The `_download_image` functions in `AdminCategorySerializer` and `AdminProductSerializer` within `backend/apps/products/admin_serializers.py` used `requests.get()` to download user-supplied image URLs without validating the host or disabling redirects, allowing an attacker to force the server to issue HTTP requests to internal IP addresses or sensitive services.
**Learning:** Even though the function expects an image URL to populate a product or category image field, standard libraries like `requests` will follow redirects by default. A seemingly valid URL (e.g., from an expected host like Cloudinary) can redirect the server's HTTP client to a malicious destination (e.g., `127.0.0.1` or AWS metadata endpoints).
**Prevention:** To prevent SSRF when fetching remote URLs, employ a two-pronged approach:
1) Strictly validate the URL scheme (`https`) and ensure the hostname is in an allowlist (e.g., checking against `IMAGE_URL_ALLOWED_HOSTS` in Django settings).
2) Explicitly pass `allow_redirects=False` to `requests.get()` to prevent attackers from bypassing the hostname validation via open redirects on allowed domains.
